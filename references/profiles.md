# Domain profiles

Starting dials per kind of project. Edit freely: these are defaults, not research findings. Pass them to `plan --dial name:min:max:current`.

| Domain | Dials worth shaking | Keep fixed |
|---|---|---|
| Language learning | session length 10-45 min; new vs review ratio; modality (listen/speak/read/write); register | grammar prerequisites, exam dates |
| Programming | kata difficulty level 1-10; time-box; language/tool constraint; read-vs-write ratio | security-sensitive code review steps |
| Maths and sciences | problem set size; interleave depth (0-3 earlier topics); worked-example vs blind attempt | prerequisite chain, safety steps in labs |
| Writing and craft | word target; form (scene, outline, edit); constraint (no adverbs, 100 words) | deadlines, submission rules |
| Music and art | tempo band; piece difficulty; copy vs compose; medium swap | injury-prevention warm-ups |
| Making (models, 3D printing, wargaming) | project size; technique to try; paint/print time-box; reference vs freehand | ventilation, blade and heat safety |
| Research and reading | papers per week; depth (skim/annotate/replicate); adjacent-field pick | citation accuracy |
| Fitness and physical skills | treat with care: vary exercise selection and order only | loads, progression caps, medical limits. Do not randomise intensity. |

## Level scale (1-10) for `log` and `next`

Define it per skill in one line before starting, for example "Python: 1 = print statements, 4 = functions and files, 7 = async and packaging, 10 = designing a library". The numbers mean nothing without that line.

## Tier rule

For prerequisite-heavy subjects, group items into tiers. Shuffle inside a tier, never across. A random order that teaches integrals before limits is just confusion with extra steps.
